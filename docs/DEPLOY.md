# التشغيل والرفع (خطوة بخطوة)

كل النظام يشتغل بأمر واحد عن طريق **Docker**: قاعدة بيانات PostgreSQL، Redis، الباك اند (API + اتصالات مباشرة)،
الواجهة، و Caddy (البوابة اللي توزع الطلبات وتسوي HTTPS).

```
الموبايل/الحاسبة ──https──▶ Caddy ──┬── /           ▶ الواجهة (Next.js)
                                    ├── /api /media ▶ web  (gunicorn: عمليات × threads)
                                    └── /ws         ▶ ws   (uvicorn: WebSocket)
                                           │
                               PostgreSQL ◀┴▶ Redis (يربط كل العمال ببعض للرسائل المباشرة)
```

---

## 0) الأسهل: على حاسوبك مباشرة من دون Docker (Linux أو macOS)

```bash
cd chat
./run-mobile.sh
```
- يثبّت المكتبات، ويجهّز قاعدة البيانات، ويبني الواجهة، ثم يشغّل الخادم والواجهة ونفقاً آمناً.
- يطبع رابط `https://….trycloudflare.com` ورمز QR: امسحه بكاميرا الهاتف.
- المرة القادمة (إن لم يتغير الكود): `./run-mobile.sh --fast`.
- للإيقاف: `Ctrl+C`. السجلات في مجلد `.run/`.
- إن كان المنفذ 8000 أو 3000 مشغولاً بخادم سابق من المشروع (مثل `runserver` في طرفية أخرى)، يعرض السكربت
  اسمه ويسألك هل يوقفه؛ و`--force` يوقفه دون سؤال. وإن كان برنامجاً آخر فلا يمسّه ويطبع أمر إيقافه.
- رسائل السكربت بالإنجليزية لأن طرفية VS Code لا تعرض العربية من اليمين إلى اليسار.

## 1) تجربة من الموبايل اليوم (رابط https مؤقت، بدون سيرفر ولا دومين)

تحتاج جهاز بيه Docker (لابتوبك يكفي). نزّل **Docker Desktop** وشغله.

```bash
git clone https://github.com/saffi277/chat.git
cd chat/deploy
./start.sh
```

- أول مرة ياخذ كم دقيقة (يبني الصور). يسوي ملف `.env` بمفاتيح عشوائية لحاله.
- بالنهاية يطبع رابط مثل `https://xxxx-yyyy.trycloudflare.com` ← افتحه من أي موبايل، بأي شبكة.
- الرابط **مؤقت**: يتغير كل ما تعيد التشغيل، ويشتغل بس لما جهازك شغال.
- بدون رابط (بس على نفس الجهاز): `./start.sh local` ← `http://localhost`.

### أول حساب إداري
```bash
docker compose exec web python manage.py createsuperuser
```
بعدها لوحة الإدارة على `الرابط/admin`: الحسابات، طلبات "نسيت كلمة المرور"، وتغيير كلمات المرور.

أو الأسهل: اجعل حسابك في التطبيق نفسه مدير نظام (باسم المستخدم أو البريد أو الرقم الجامعي):
```bash
docker compose exec web python manage.py make_admin اسم-المستخدم
```
فتظهر لك في التطبيق: الإعدادات ← **لوحة الإدارة** (طلبات الأدوار، ونسيت كلمة المرور، والبلاغات).

### تجربة الموبايل: شنو تتأكد منه
| الشي | أندرويد (كروم) | آيفون (سفاري) |
|---|---|---|
| الدخول والمحادثات | ✅ مباشرة | ✅ مباشرة |
| المايك (رسالة صوتية) والكاميرا (مكالمة فيديو) | ✅ يسأل أول مرة | ✅ يسأل أول مرة |
| الإشعارات والتطبيق مسدود | ✅ من الإعدادات ← الإشعارات | ⚠️ لازم أول: زر المشاركة ← **إضافة إلى الشاشة الرئيسية**، وتفتحه من الأيقونة (iOS 16.4 أو أحدث) |

- الأذونات كلها بـ **الإعدادات ← الأذونات**: حالة كل واحد وزر "سماح". إذا انرفض، يطلع شرح شلون يتفعل حسب الجهاز.
- المكالمات بين شبكتين مختلفتين (مثلاً هاتف على بيانات الجوال وحاسوب على واي فاي) تحتاج غالباً خادم ترحيل **TURN**
  (انظر القسم التالي). على شبكة الواي فاي نفسها تعمل دونه. إن تعذّر الاتصال تنتهي المكالمة بعد 25 ثانية برسالة توضّح ذلك.

### تفعيل خادم TURN (مكالمات بين أي شبكتين)
**بدونه** تنجح المكالمة بين جهازين على الشبكة نفسها فقط، وتبقى «جارٍ الاتصال» بين شبكتين مختلفتين
(مثلاً هاتف على بيانات الجوال وحاسوب على واي فاي)، ثم تنتهي بعد 25 ثانية.

**الأسهل على السيرفر: خادمنا coturn، بأمر واحد** (يولّد السرّ، ويكتشف عنوان السيرفر، ويفتح المنافذ إن كان ufw مفعّلاً):
```bash
cd ~/chat/deploy && ./enable-turn.sh
```
- افتح في جدار حماية شركة الاستضافة (لوحة التحكم) المنافذ: **3478** (UDP وTCP) و**49160-49200** (UDP).
- من بعدها يصير أمر التحديث: `docker compose --profile tunnel --profile turn up -d --build`.
- كلمات السر مؤقتة (يوم واحد) يولّدها الخادم لكل مستخدم من `TURN_SECRET`، فلا يستطيع أحد استعمال خادمنا للأبد إن نسخها.

أو بدلاً منه، مفتاح واحد من هذه الطرق في متغيرات البيئة قبل التشغيل (أو في `deploy/.env`):
- **Cloudflare (مجاني بحصة كبيرة):** من لوحة Cloudflare ← Realtime ← TURN ← أنشئ مفتاحاً، ثم:
  ```bash
  export CLOUDFLARE_TURN_KEY_ID=...  CLOUDFLARE_TURN_API_TOKEN=...
  ./run-mobile.sh --fast
  ```
- **Metered أو أي خدمة تعطي رابطاً يعيد قائمة iceServers:** ‏`export TURN_CREDENTIALS_URL="https://…/api/v1/turn/credentials?apiKey=…"`
- **خادم خاص (coturn):** ‏`export TURN_URLS=turn:your.server:3478 TURN_USERNAME=… TURN_CREDENTIAL=…`

يمكن التحقق: ‏`curl -H "Authorization: Token <token>" http://localhost:8000/api/calls/ice/` يجب أن يظهر فيه عنوان يبدأ بـ `turn:`.

### الإشعارات على الآيفون لا تظهر؟
1. **الرقم على أيقونة التطبيق ليس إشعاراً**: يضعه التطبيق نفسه وهو مفتوح (عدد الرسائل غير المقروءة).
   الإشعار الحقيقي بطاقة في مركز الإشعارات مع صوت واهتزاز.
2. داخل التطبيق: الإعدادات ← الإشعارات ← **إرسال إشعار تجريبي**، ثم أغلق التطبيق فوراً. يصل بعد 5 ثوانٍ،
   وإن رفضته خدمة الإشعارات تظهر رسالة بالسبب.
3. في الآيفون: الإعدادات ← الإشعارات ← وَصل ← **السماح بالإشعارات** + **اللافتات** + **الأصوات**.
   وضع **التركيز** (Focus) أو مفتاح **الصامت** يمنعان الصوت والاهتزاز.
4. بعد تحديث الخادم: أوقف الإشعارات من داخل التطبيق ثم فعّلها من جديد (يُنشئ اشتراكاً جديداً).
5. سجل الخادم يبيّن سبب أي رفض: `grep "push failed" .run/backend.log`.

### أوامر تحتاجها
```bash
docker compose ps                 # شنو شغال
docker compose logs -f web        # سجل الـ API
docker compose --profile tunnel down   # إيقاف كلشي (البيانات تبقى)
```

## 2) الرفع على سيرفر حقيقي (لما يصير عندكم سيرفر ودومين)

1. سيرفر Linux (مثلاً 8 معالجات و16 گيگا رام لـ 2000+ مستخدم بنفس الوقت) عليه Docker.
2. خلي الدومين (مثلاً `chat.asbat.edu.iq`) يأشر على IP السيرفر (سجل A).
3. بالسيرفر:
   ```bash
   git clone https://github.com/saffi277/chat.git && cd chat/deploy
   cp .env.example .env
   ```
   وعدل `.env`:
   ```
   SECRET_KEY=نص-عشوائي-طويل
   POSTGRES_PASSWORD=كلمة-سر-قوية
   SITE_ADDRESS=chat.asbat.edu.iq
   ALLOWED_HOSTS=chat.asbat.edu.iq
   CSRF_TRUSTED_ORIGINS=https://chat.asbat.edu.iq
   ```
4. `docker compose up -d --build` ← Caddy يجيب شهادة HTTPS لحاله ويجددها.
5. افتح المنفذين 80 و 443 بجدار الحماية.

### ⚠️ النسخ الاحتياطي (مهم جداً)
الرسائل والملفات **مشفرة**، ومفتاح التشفير بـ volume اسمه `keys`. **إذا ضاع المفتاح، الرسائل ما تنقرا أبداً.**
```bash
# قاعدة البيانات
docker compose exec db pg_dump -U wasl wasl > backup.sql
# المفاتيح (مفتاح الرسائل + مفاتيح الإشعارات) ← احفظها بمكان آمن بعيد عن السيرفر
docker compose cp web:/app/keys ./keys-backup
# الملفات المرفوعة (مشفرة)
docker compose cp web:/data/media ./media-backup
```

### التوسع (إذا زاد الضغط)
- زيد العمال بـ `.env`: `WEB_WORKERS`, `WEB_THREADS`, `WS_WORKERS`.
- أو أكثر من نسخة: `docker compose up -d --scale web=3 --scale ws=3` (Redis يربطهم كلهم ببعض).
- قاعدة البيانات تتحمل 300 اتصال (`max_connections`)؛ إذا زدت العمال هواية، زيدها أو حط PgBouncer.

## 3) اختبار الضغط (2000 مستخدم بنفس اللحظة)

يشتغل من نفس المكان اللي بيه الباك اند (مو من داخل Docker):
```bash
cd backend && python manage.py loadtest_users --count 2000   # 2000 حساب ومحادثات ومجموعات (وتوكناتهم بـ /tmp/lt_users.json)
cd ../loadtest && pip install -r requirements.txt
python run.py --base http://localhost --users 2000 --procs 4 --ramp 60 --label test
```
النتيجة تنكتب بـ `/tmp/lt_result_test.json`، ونتائجنا محفوظة بـ `loadtest/results/`.
للمسح بعدين: `python manage.py loadtest_users --delete`. آخر نتيجة (كلشي على جهاز واحد 4 معالجات، ومولّد الضغط نفسه ياكل نص المعالج):

| | قبل (SQLite + عملية وحدة) | بعد (PostgreSQL + Redis + عدة عمال) |
|---|---|---|
| اتصلوا (WebSocket) | 99 من 2000 | **2000 من 2000** |
| جابوا المحادثات | 36 | **2000** |
| رسائل انرسلت | 0 | **7974** |
| وقت الاتصال (نص المستخدمين) | 4.8 ثانية | **0.9 ثانية** |

على سيرفر حقيقي (معالجات أكثر، ومولّد الضغط بجهاز ثاني) الأرقام تتحسن هواية.

### إعادة الاختبار بعد المراحل (أ)-(د) (29 أيلول 2026)

**طريقة القياس:**
- الجهاز نفسه: 4 معالجات، والخادم ومولّد الضغط معاً.
