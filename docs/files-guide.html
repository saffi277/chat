كل ملف في المشروع: عمله، ومحتواه، ولغته

افتح المشروع في VS Code وهذا الدليل بجانبه. ستجد فيه لكل ملف ما يفعله وما في داخله، وكيف تعرف اللغة وإطار العمل بنفسك، وماذا تقول للمدير إن سألك، وشرح ملف الإعدادات سطراً بسطر. الأقسام والعناوين مرقّمة؛ فإن لم تفهم نقطة فأخبرني برقمها، مثلاً: «لم أفهم 6.3».

1الصورة الكبيرة: ثلاثة أجزاء

حين تفتح المجلد chat/ في VS Code ترى في الشريط الجانبي هذه المجلدات الرئيسية:

chat/
├── backend/        الخادم: العقل والذاكرة (Python + Django)
├── frontend/       الواجهة: ما يراه المستخدم (TypeScript + Next.js)
├── deploy/         تشغيل النظام على خادم حقيقي (Docker)
├── docs/           التوثيق والتقارير (منها هذا الملف)

├── run-mobile.sh   تشغيل النظام على حاسوبك مع رابط للهاتف
└── README.md       التعريف بالمشروع

الخادم Python

يستقبل الطلبات، ويتحقق من هوية المستخدم، ويحفظ الرسائل مشفّرة في قاعدة البيانات، ويبثّها فوراً. إطاره: Django.

الواجهة TypeScript

الشاشات والأزرار التي يراها الطالب في المتصفح أو الهاتف، وتطلب البيانات من الخادم. إطارها: Next.js مع React.

الجزءان منفصلان تماماً ويتحدثان عبر الشبكة بطريقتين: HTTP (سؤال وجواب، مثل «أعطني محادثاتي») وWebSocket (خط مفتوح دائماً للرسائل الفورية).

2.2الطريقة الثانية: VS Code يخبرك بنفسه

افتح أي ملف، وانظر إلى الشريط السفلي في VS Code، في الزاوية اليمنى. ستجد اسم اللغة مكتوباً: Python عند فتح ملف ‎.py، وTypeScript JSX عند فتح ملف ‎.tsx، وTypeScript عند فتح ملف ‎.ts. وأيقونة الملف في الشريط الجانبي تدل عليها أيضاً: ثعبان أزرق وأصفر لـ Python، ومربع أزرق مكتوب فيه TS لـ TypeScript.

2.3الطريقة الثالثة: شكل الكود نفسه

الدالة نفسها من مشروعنا بالطريقتين:

Python من backend/chat/views.py

def name_of(user):
    return profile_of(user).display_name or user.username

• تبدأ الدالة بـ def
• لا أقواس معقوفة { }؛ الإزاحة (المسافات) هي التي تحدد الكتلة
• التعليق يبدأ بـ #
• الاستيراد: from django.db import models

TypeScript من frontend/app/chat/_ui/bits.tsx

export const nameOf = (u: Pick<User, "display_name" | "username">) =>
  u.display_name || u.username;

• const و=> والأقواس المعقوفة
• التعليق يبدأ بـ //
• الاستيراد: import { x } from "y"
• وعلامة TypeScript تحديداً: الأنواع بعد النقطتين u: User

2.4كيف تفرّق TypeScript عن JavaScript؟

هما متشابهتان جداً، لأن TypeScript هي JavaScript مع «الأنواع». أربع علامات تكفي:

  1. الامتداد: .ts أو .tsx تعني TypeScript، و.js أو .jsx تعني JavaScript.
  2. الأنواع بعد النقطتين: name: string، id: number، user: User. هذه غير موجودة في JavaScript.
  3. تعريف الأنواع بكلمتَي type أو interface. مثال من frontend/lib/api.ts: export type User = { id: number; username: string; ... }.
  4. وجود الملف frontend/tsconfig.json، وهو إعدادات TypeScript، وكلمة "typescript" داخل frontend/package.json.

3كيف تعرف إطار العمل؟

تذكير: اللغة هي ما نكتب به (Python، TypeScript)، وإطار العمل هيكل جاهز مكتوب بتلك اللغة نبني داخله (Django، Next.js). ولكل إطار «بصمات» في الملفات:

3.1بصمات Django في الخادم

  • الملف backend/manage.py: موجود في كل مشروع Django، وبه نشغّل الأوامر (python manage.py runserver).
  • الملف backend/config/settings.py وفيه INSTALLED_APPS وMIDDLEWARE: أسماء خاصة بـ Django.
  • في backend/requirements.txt (قائمة المكتبات): Django==5.2.17 وdjangorestframework وchannels.
  • في أول كل ملف: from django.db import models، وfrom rest_framework ... (وهو Django REST Framework)، وfrom channels ... (وهو Django Channels).
  • كل «تطبيق» مجلد فيه الملفات نفسها: models.py، views.py، urls.py، admin.py، apps.py، migrations/. هذا تنظيم Django المعروف.

3.2بصمات Next.js وReact في الواجهة

  • في frontend/package.json: "next": "16.3.6" و"react": "19.2.8"، والأوامر next dev وnext build.
  • الملف frontend/next.config.ts: إعدادات Next.js.
  • المجلد frontend/app/ وفيه ملفات بأسماء ثابتة: layout.tsx وpage.tsx. هذا «App Router» في Next.js: كل مجلد فيه page.tsx يصبح صفحة. فالمجلد app/login/ هو الصفحة /login.
  • في الكود: import ... from "next/navigation" (Next.js)، وuseState وuseEffect والوسوم مثل <div className="..."> (React).
  • Tailwind CSS (للتنسيق): الأسماء القصيرة في className مثل "flex items-center gap-3"، والملف postcss.config.mjs.

4ماذا تقول للمدير، وكيف تُثبت له

4.1الجواب في جملتين

«الخادم مكتوب بلغة Python بإطار Django، ومعه Django REST Framework للـ API وDjango Channels للرسائل الفورية. والواجهة مكتوبة بلغة TypeScript بإطار Next.js مع React.»

4.2إن سألك: «كيف عرفتَ أنها TypeScript؟»

افتح VS Code وأره هذه الأدلة الخمسة بالترتيب:

  1. امتداد الملفات: افتح frontend/app/chat/_ui/ وأشر إلى الأسماء: ChatList.tsx، Conversation.tsx. والامتداد .tsx يعني TypeScript.
  2. الشريط السفلي في VS Code: افتح أي واحد منها، وسيظهر في الزاوية اليمنى السفلى TypeScript JSX.
  3. الأنواع في الكود: افتح frontend/lib/api.ts وأره export type User = { id: number; username: string; ... }، وقل: «هذا تعريف نوع، ولا يوجد في JavaScript».
  4. ملف إعدادات TypeScript: frontend/tsconfig.json، وفيه "strict": true أي الفحص الصارم للأنواع.
  5. قائمة المكتبات: frontend/package.json، وفيه "typescript": "^5" و"next": "16.3.6".

4.3وإن سألك: «ولماذا TypeScript لا JavaScript؟»

«لأنها تكشف الأخطاء قبل التشغيل؛ فلو كتبتُ اسم حقل خطأ أو مرّرتُ رقماً مكان نص، تنبّهني فوراً. وهي الخيار الافتراضي الذي يقترحه Next.js نفسه، وعند البناء تتحول إلى JavaScript عادية يفهمها المتصفح.»

4.4وإن سألك عن الخادم: «كيف عرفتَ أنه Django؟»

أره backend/manage.py، ثم backend/requirements.txt وفيه Django==5.2.17، ثم أول سطر في backend/chat/models.py: from django.db import models.

5ملف الإعدادات: ماذا فيه؟

حين يُقال «ملف الإعدادات» في مشروع Django فالمقصود backend/config/settings.py (233 سطراً، بلغة Python). هو المكان الذي يقرر كيف يعمل الخادم كله. هذه محتوياته بالترتيب نفسه الذي تراه حين تفتحه:

5.1الأمان والعناوين

الإعدادمعناه
SECRET_KEYمفتاح سري يستعمله Django لتوقيع البيانات (ومنها روابط الملفات الموقّعة). في التشغيل الفعلي يأتي من ملف .env لا من الكود.
DEBUGوضع التطوير: يُظهر تفاصيل الأخطاء. يجب أن يكون false في التشغيل الفعلي حتى لا تُكشف التفاصيل للناس.
ALLOWED_HOSTSالعناوين (النطاقات) التي يقبل الخادم أن يُفتح منها.
CSRF_TRUSTED_ORIGINSالمواقع الموثوقة لطلبات النماذج (حماية من هجمات CSRF)، ومنها رابط النفق المؤقت.
SECURE_PROXY_SSL_HEADERيخبر Django أن الطلب الأصلي كان https حين يمرّ عبر البوابة (Caddy).

5.2مكوّنات النظام

الإعدادمعناه
INSTALLED_APPSقائمة «التطبيقات» المفعّلة: أدوات Django الجاهزة (لوحة الإدارة، والحسابات...)، ثم rest_framework (الـ API)، وchannels (WebSocket)، وcorsheaders، ثم تطبيقاتنا الخمسة: accounts، chat، notifications، stories، calls. وdaphne أولها لأنه خادم التطوير الذي يشغّل HTTP وWebSocket معاً.
MIDDLEWARE«محطات» يمرّ بها كل طلب قبل الوصول إلى الكود: الأمان، والسماح للواجهة بالاتصال (CORS)، واللغة (العربية أو الإنجليزية من ترويسة Accept-Language)، والحماية من CSRF، والتعرف على المستخدم.
ROOT_URLCONFملف الروابط الرئيسي: config/urls.py.
TEMPLATES وWSGI_APPLICATIONإعدادات Django الافتراضية للقوالب (نستعملها للوحة الإدارة فقط) ولخادم WSGI.
ASGI_APPLICATIONنقطة الدخول التي تدعم WebSocket: config/asgi.py.

5.3قاعدة البيانات وكلمات المرور

الإعدادمعناه
DATABASESأي قاعدة بيانات نستعمل: PostgreSQL إن وُجد المتغير DATABASE_URL، وإلا فملف SQLite backend/db.sqlite3. ويُعاد استعمال الاتصال 60 ثانية (conn_max_age).
PASSWORD_HASHERSكيف تُحفظ كلمات المرور: هاش Argon2 أولاً، والباقي للحسابات القديمة فقط.
AUTH_PASSWORD_VALIDATORSقواعد كلمة المرور: ألا تشبه اسم المستخدم، وألا تكون قصيرة، ولا شائعة، ولا أرقاماً فقط.

5.4اللغة والوقت والملفات

الإعدادمعناه
LANGUAGE_CODE وLANGUAGES وLOCALE_PATHSالعربية افتراضياً، والإنجليزية لغة ثانية، وملف الترجمة في backend/locale/.
TIME_ZONE وUSE_TZالخادم يحفظ الأوقات بتوقيت عالمي (UTC)، والواجهة تعرضها بتوقيت هاتف المستخدم.
STATIC_URL وSTATIC_ROOTملفات لوحة الإدارة الثابتة (تنسيقها وصورها).
MEDIA_URL وMEDIA_ROOTأين تُحفظ الملفات المرفوعة (الصور والصوت والمستندات): backend/media/.
KEYS_DIRأين يوجد مفتاح التشفير ومفاتيح الإشعارات.
DATA_UPLOAD_MAX_MEMORY_SIZEأكبر طلب مقبول: 60 ميغابايت (الفيديو حتى 50).
DEFAULT_AUTO_FIELDنوع رقم التعريف (id) في الجداول: رقم كبير يكفي لمليارات الصفوف.

5.5السرعة والحماية من الضغط

الإعدادمعناه
REDIS_URL وCHANNEL_LAYERS وCACHESإن وُجد Redis فهو «لوحة الإعلانات» التي يتبادل عبرها العمّال الرسائل الفورية، والذاكرة المؤقتة. وإلا فنسخة في الذاكرة تكفي للتطوير.
REST_FRAMEWORKإعدادات الـ API: الهوية بالتوكن (هاشه فقط محفوظ)، وكل الروابط تتطلب الدخول، وحدود الطلبات في الدقيقة: 600 للمستخدم، و120 لغير المسجّل، و20 لمحاولات الدخول، و120 لإرسال الرسائل.
THROTTLING_ENABLEDتشغيل حدود الطلبات (وتُطفأ أثناء الاختبارات الآلية فقط).
CORS_ALLOWED_ORIGINSالمواقع المسموح لها أن تتصل بالـ API (الواجهة على المنفذ 3000).

5.6الإشعارات والمكالمات والسجلات

الإعدادمعناه
VAPID_CONTACTعنوان تواصل يُرسَل إلى خدمات الإشعارات. يجب أن يكون حقيقياً، وإلا ترفضه Apple فلا تصل الإشعارات إلى الآيفون.
LOGGINGطباعة تحذيرات الإشعارات في الطرفية لمعرفة سبب أي فشل.
ICE_SERVERSخوادم STUN التي تساعد الجهازين على إيجاد بعضهما في المكالمات (وخادم TURN يُضاف من متغيرات البيئة).
لماذا تبدأ قيم كثيرة بـ os.environ.get(...)؟معناها: «اقرأ القيمة من متغيرات البيئة (ملف .env على الخادم)، وإن لم توجد فاستعمل القيمة الافتراضية للتطوير». هكذا لا تُكتب الأسرار (كلمات السر والمفاتيح) داخل الكود، ولا تُرفع إلى GitHub.

6ملفات الخادم: مجلد backend

قاعدة تختصر عليك نصف الملفاتالخادم مقسّم إلى «تطبيقات» Django، وكل تطبيق مجلد له الملفات نفسها بالمعنى نفسه:
• __init__.py: ملف فارغ يجعل المجلد «حزمة» Python يمكن الاستيراد منها. لا تعدّله.
• apps.py: تسجيل التطبيق في Django (سطور قليلة ثابتة).
• models.py: الجداول في قاعدة البيانات.
• views.py: منطق الـ API: ماذا يحدث عند كل طلب.
• urls.py: الروابط: أي رابط يذهب إلى أي دالة في views.py.
• serializers.py: تحويل البيانات بين Python وJSON.
• admin.py: ما يظهر في لوحة الإدارة /admin.
• tests.py: الاختبارات الآلية.
• migrations/: سجلّ تغييرات الجداول، يولّده Django (القسم 9).
• management/commands/: أوامر إضافية تُشغَّل بـ python manage.py اسم_الأمر.

6.1ملفات في جذر backend/

الملفاللغةعمله ومحتواه
manage.pyPythonبوابة أوامر Django: runserver للتشغيل، migrate لتحديث الجداول، test للاختبارات. ملف قياسي لم نعدّله.
requirements.txtنصالمكتبات وإصداراتها: Django، وDRF، وChannels، وDaphne، وUvicorn، وGunicorn، وRedis، وPostgreSQL (psycopg)، وArgon2، وpywebpush، وPillow...
DockerfileDockerوصفة بناء «حاوية» الخادم: Python 3.12، ثم تثبيت المكتبات ونسخ الكود.
entrypoint.shShellما يحدث عند تشغيل الحاوية: ينتظر قاعدة البيانات، ثم migrate، ثم يشغّل Gunicorn (للـ API) أو Uvicorn (للـ WebSocket) بعدد عمّال مناسب.
.dockerignoreنصملفات لا تُنسخ إلى Docker: قاعدة بيانات التطوير، والملفات المرفوعة، والمفاتيح.

10أسئلة المدير المتوقعة وأجوبتها

10.1 ما لغة المشروع؟

الخادم Python بإطار Django، والواجهة TypeScript بإطار Next.js مع React (القسم 4).

10.2 أين ملف الإعدادات؟ وماذا فيه؟

backend/config/settings.py: فيه الأمان (SECRET_KEY وDEBUG)، والتطبيقات المفعّلة، وقاعدة البيانات، وهاش كلمات المرور (Argon2)، واللغة، وRedis، وإعدادات الـ API وحدود الطلبات، وأماكن الملفات، والإشعارات، والمكالمات (القسم 5). والأسرار تأتي من ملف .env لا من الكود.

10.3 أين الـ API؟

الروابط في backend/*/urls.py، ومنطقها في backend/*/views.py، وأكبرها backend/chat/views.py. وفي الواجهة تُستدعى من frontend/lib/endpoints.ts.

10.4 أين قاعدة البيانات والجداول؟

تعريف الجداول في backend/*/models.py. في التطوير ملف backend/db.sqlite3، وفي التشغيل الفعلي PostgreSQL داخل Docker.

10.5 أين الهاش والتشفير؟

هاش كلمات المرور: PASSWORD_HASHERS في settings.py (Argon2). هاش التوكن: backend/accounts/tokens.py. تشفير الرسائل والملفات: backend/chat/crypto.py وfields.py.

10.6 أين الرسائل الفورية (WebSocket)؟

الخادم: backend/chat/consumers.py وrouting.py. الواجهة: frontend/lib/socket.ts.

10.7 أين الشاشات؟

في frontend/app/chat/_ui/، وكل شاشة في ملف باسمها (القسم 7.3)، وبوابة الدخول في frontend/app/AuthForm.tsx.

10.8 كيف تشغّل المشروع؟

على الحاسوب: ./run-mobile.sh. على خادم حقيقي: cd deploy && ./start.sh (Docker). والاختبارات: cd backend && python manage.py test.

10.9 ما الفرق بين views.py وurls.py وmodels.py؟

models.py يعرّف الجداول (ماذا نحفظ)، وviews.py يقرر ماذا يحدث عند كل طلب (المنطق)، وurls.py يربط كل رابط بدالته في views.py. مثال: الرابط /api/conversations/ في urls.py يذهب إلى الدالة conversations في views.py، التي تقرأ من جدول Conversation المعرّف في models.py.
